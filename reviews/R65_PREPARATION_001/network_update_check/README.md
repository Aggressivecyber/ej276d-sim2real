This folder prepares an artificial check of the selected R65 joint D+C update. The actual ResponseNetwork, original endpoint/Box/ADC path and original loss definitions are imported from the byte-bound objective adapter bundle. No scientific arrays or trained weights are read. Preparation is static only; actual CPU and CUDA checks have not been executed locally.

The portable entry is `network_update_check.run_check(device="cpu", *, objective_adapter_root=...)`. Copy this folder with its JSON files and the bound sibling `objective_adapter` folder to the root-owned server area. Import the module under the existing supervised process and call the entry with the explicit adapter directory. The caller must use Python `-B`, ordinary autograd, float32 default parameters with CPU model construction, deterministic algorithms, disabled MHA fastpath, disabled TF32/benchmark, deterministic cuDNN and no autocast. The caller owns thread settings, resource limits, CUDA selection, logs and result writes. This helper does not change thread or backend policies. It uses a scoped CPU RNG fork for artificial model initialization and checks that caller RNG/backend/thread state is restored.

Both variants include one original C graph with 320 SOURCE occurrences and 64 REAL identity rows. The CPU D population has 13 SOURCE and 23 REAL parents in ten nonempty uneven regions, with schedule 4+4+4+1. CUDA uses 65 SOURCE and 75 REAL parents with schedule 64+1. The local 1 GiB preparation guard must never call this fixture. Actual execution belongs to the root server supervisor with its 48 GiB process-tree RSS and 10 GiB GPU limits; those limits do not imply that this as-yet-unexecuted fixture fits them.

The reference arm builds one scalar joint full D plus the four original C pieces on a single graph, using the same D chunks, source inputs, artificial state and C384 graph as the replay arm. The replay arm collects all D endpoints, calls `joint_total_D` for one total endpoint derivative, recomputes the same chunks, sums parameter VJPs on CPU float64, adds one original C parameter gradient, installs the sum once, clips once at 5 and performs one artificial Adam step. There are two total artificial optimizer steps if both comparison arms complete. No scientific update is permitted by this helper.

The shared trainer functions are:

- `parameter_vjp_cpu_f64(output, parameters, gradient)`: one VJP at the projected pre-ADC float64 output with a detached float64 GY on the same device; returns a detached flat CPU float64 vector in the supplied parameter order. GY already contains objective masses, normalizations and canonical STE. There is no added parent average or mass factor.
- `scalar_parameter_gradient_cpu_f64(scalar, parameters, *, retain_graph=False)`: one scalar reverse pass through the supplied complete graph, returning the same CPU float64 vector format.
- `install_cpu_f64_clip_step(parameters, gradient_cpu_f64, optimizer, *, clip=5.0, capture=False)`: requires `.grad is None` for every parameter and identical optimizer parameter ordering. It casts each slice once to that parameter's dtype/device, calls `clip_grad_norm_` once and `optimizer.step()` once. It neither zeroes gradients nor changes the optimizer LR/settings.

Update metadata always includes `pre_clip_norm` as a Python float, `did_clip`, `clip_coefficient`, `cast_calls=1`, `parameter_tensor_cast_calls`, `clip_calls=1`, `optimizer_calls=1` and `optimizer_step_calls=1`. `cast_calls` counts one complete vector installation; `parameter_tensor_cast_calls` counts its individual tensor conversions. `did_clip` means the coefficient used by the standard `clip/(norm+1e-6)` rule is below one. `capture=True` additionally returns CPU float64 `before_clip` and `after_clip` tensors for testing; these two tensors must be removed or serialized separately if the caller logs this shared function's raw return value. The full `run_check` return itself is JSON-compatible.

`FROZEN_TOLERANCES.json` and `FIXTURE_SPEC.json` were written before any network execution. Endpoint/raw values, canonical codes, strict Box free masks and the joint endpoint derivative must replay exactly. D, C, combined pre-cast, once-cast and clipped parameter gradients use the unchanged R64 relative L2 and maximum-error bounds. Every named parameter participates. Four C endpoint signals, both Box paths, source-order denominator/decomposition, charge preservation and active clipping are checked. The C call computes the original nine pieces and discards the five old microbatch D pieces without differentiating them into the selected objective.

The first Adam step can amplify tiny near-zero gradient differences. The frozen update/state check therefore evaluates the exact first-step mathematical formula in float64 from each arm's actual clipped gradient, checks moments and parameters with fixed float32 arithmetic/ULP allowances, and compares the observed inter-arm differences with the predicted differences. It also reports raw inter-arm differences. This is coupled to the tight full-gradient gate; it is not a bitwise parameter-equality claim or a large arbitrary parameter atol. These bounds must not be relaxed after seeing execution results.

On success `run_check` returns `passed`, `status`, `compact`, `checks`, `values`, `Adam_comparison`, source/tolerance/fixture hashes, synthetic state hashes, update-attempt metadata, caller-state fingerprints, selected device, versions and elapsed time. Failure raises `ArtificialNetworkCheckFailure` carrying `.receipt`, including any partial checks and successful synthetic step count. The helper does not write a result. A started but unfinished cast/clip/step call is explicitly retained as an unresolved attempt; a process killed by a resource guard also needs the external native receipt.

`SOURCE_BINDING.json` binds the whole helper, frozen inputs and the explicit objective source bundle. The portable check verifies them before and after execution. The trainer's direct use of the three shared functions does not itself perform source-file I/O; the root must bind this same helper SHA in its driver/protocol and transfer manifest.

`static_check.py validate` performs only guarded source/JSON reads, AST parsing and compilation, literal tolerance comparison with the R64 architecture fixture, API and source-hash checks. It never imports this helper, NumPy or PyTorch and never constructs a network. `STATIC_RECEIPT.json`, `PREPARATION_RECEIPT.json`, the resource receipt and native exit receipt describe this preparation only. Passing these static checks does not establish numerical correctness, resource feasibility, TRAIN performance or A–F acceptance.
